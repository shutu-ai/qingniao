# 青鸟 Phase 1(M0 自检 + M1 组网)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付环境自检 CLI(Qingniao.SelfCheck)与组网守护进程(Qingniao.MeshDaemon):真机两节点经 mDNS/VPN 网段自动建立 Yggdrasil peering,自检工具一页报告 IPv6/NAT 类型/硬编/VPN 可达。

**Architecture:** 分层与设计文档 §7 一致:Qingniao.Mesh 托管 yggdrasil 子进程(生成最小 YAML 配置 + admin socket 通信 + 看门狗);Qingniao.LinkManager 负责 VPN CIDR 探测与 mDNS 通告/发现,发现的节点经 admin socket 幂等注入 `addPeer`;Qingniao.SelfCheck 是独立 CLI,复用 LinkManager 的探测器。本阶段所有链路都是"监听 + TCP addPeer"模式,打洞属 M3,不在本计划。

**Tech Stack:** C# / .NET 10 LTS(net10.0)、xUnit、System.Text.Json、Makaretu.Dns.Multicast(mDNS)、TimeProvider(测试时钟)。外部二进制:yggdrasil v0.5.6(不入库)。

**Spec:** `C:\dev-projects\Workshop\qingniao\docs\superpowers\specs\2026-11-11-qingniao-design.md`(§7 架构、§10 组网、§11 M0/M1 验收;实现者须同读)

- 目标框架 `net10.0`,全局 `Nullable=enable`、`ImplicitUsings=enable`、`TreatWarningsAsErrors=true`、`LangVersion=latest`
- 运行环境:Windows 10/11 x64;运行步骤均在开发者机器 PowerShell 执行
- MeshPort=**13371**,AdminPort=**13372**(MeshConfig 默认值,不得改名)
- STUN 默认服务器:`stun1.l.google.com:19302`、`stun.cloudflare.com:3478`
- yggdrasil 固定 v0.5.6(下载见 Task 1),存放 `tools/yggdrasil/`,**不提交入库**
- 无厂商云、无遥测;公共 STUN 仅用于探测,不作信任锚
- 提交信息 conventional commits(`feat:`/`test:`/`chore:`…),不加任何署名尾行
- 严格 TDD:每个任务先写失败测试再实现;默认测试命令统一为
  `dotnet test --filter Category!=Live`(联网/真机验证用 `--filter Category=Live` 单独跑)
- 纯逻辑类型一律不可变(record / IReadOnlyList),状态更新返回新快照

## Review Focus

按设计文档 §Review 推导,以下输入类别最可能咬到使用者;每条已由对应任务的测试钉死:

1. **NAT 类型误报**(把对称 NAT 报成"可打洞")——使用者会据此误信公网直连可行。
   期望:映射地址在两个服务器间不同 ⇒ Symmetric + 明确警告文案。(Task 9 矩阵测试)
2. **STUN 服务器全部超时/不可达**——期望返回 Unknown("无法判定")并正常退出,不崩溃、不误判。(Task 8 超时测试 + Task 9 Unknown 用例)
3. **多网卡/虚拟交换机环境下 mDNS 通告错误地址**(loopback、169.254、链路本地)——期望仅通告可用单播地址。(Task 12 PeerAddressFilter 测试)
4. **yggdrasil 子进程反复崩溃导致重启风暴**——期望指数退避 1s→2s→4s…封顶 60s。(Task 5 RestartBackoff 测试)
5. **对同一节点重复 addPeer**——期望幂等:状态表已存在或 getPeers 已含端点时不发第二次请求。(Task 13 幂等测试)
